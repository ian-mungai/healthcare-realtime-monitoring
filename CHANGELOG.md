# Changelog

Notable changes to the synthetic portfolio system are recorded here. Releases use version tags; this record does not promise a stable public application interface. Historical evidence remains in the linked release notes.

## [Unreleased]

### Changed

- Keep Terraform state local and remove it at teardown, because each deployment is a short-lived demo. `infra/` has no remote backend; each `DEPLOYMENT_ENVIRONMENT` gets its own workspace, `bootstrap.sh init` initializes it and every script that reads state selects it first. `teardown.sh destroy-apply` removes the state, its backups and the saved plans once `terraform state list` is empty. Removed: the state bucket and its `infra/bootstrap` stack, `TF_STATE_BUCKET` and `TF_STATE_PREFIX`, the `state-*`, `main-init` and `main-migrate` actions, the private-configuration sync, the GitHub Deploy workflow and its GitHub OpenID Connect (OIDC) deployment role, the state-bucket deploy-policy statements and the state-bucket prerequisite checks.
- Add the early-warning endpoint, `GET /patients/{patient_id}/early-warning` on the vitals API. It returns NEWS2 from the patient's cached vitals and the approved model's real-time score of the current encounter. The stream processor keeps each encounter's readings in a new DynamoDB feature-window table (`healthcare-realtime-feature-window`, two-day expiry), including readings the latest cache skips as stale. Once the 15-minute window has closed, the endpoint scores it in plain Python from `scoring_parameters.json`, which training now publishes. It stores the score once per model version. A test checks the score equals scikit-learn's to 1e-12. `e2e.aws_early_warning` checks NEWS2 against `services/news2.py` and the live score against the batch score.
- Show live NEWS2 with its RCP 2017 risk band on the Streamlit watchlist, from the measurements still current, with the model score from the early-warning endpoint and a NEWS2 5+ count.
- Add the `healthcare_realtime_ingestion` workflow: every 30 minutes when the schedule is enabled, it checks that the FHIR webhook Lambda answers its health route, HAPI's subscription to it is active and the webhook Lambda had no errors. A failed check raises the task-failure alarm. The checks find the webhook's API by name at run time, because it is created in the same apply. The workflow generator and validator now handle every DAG; `e2e.aws_ingestion` runs the workflow once.
- Add Grafana on AWS, off unless `ENABLE_GRAFANA=true`. `deploy/grafana/Dockerfile` adds the checksum-verified Athena data source plugin 3.3.8 and the dashboards rendered for Athena (`render_dashboards --target aws`, with the database and table names from `config/deployment.defaults.json` and the quarantine receive time parsed from its string). The `grafana_ecs` module runs one private Fargate task with no inbound rule, read-only Athena access and ECS Exec; operators reach it through an SSM port forward. Its admin password comes from the `healthcare-realtime/grafana-admin` secret, which the operator creates before the apply, so its value never enters Terraform. The deployment policies only describe and read it; the prerequisite check confirms it exists. `push_images.sh` builds the fifth image and the deploy policies allow the port forward and the secret. `e2e.aws_grafana` runs the local panel checks on Athena.
- Plan the local containers' memory at launch instead of leaving them unlimited. `scripts/local/local_stack.sh start` writes each service's limit to an ignored Compose override from the memory free at that moment (`tools/memory_budget.py`), HAPI FHIR's heap follows its limit and `e2e.local_stack` checks every container has one. The lock compiler gives its container the same kind of computed limit. Docker's memory is shared with other projects' containers, so no limit is fixed.
- Add statsmodels 0.15.0, JupyterLab 4.6.4 and nbconvert 7.17.1 to the development lock for the local analysis notebooks. `tools/compile_requirements.py` now adds each pinned requirement with an environment marker in a source to its lock with every PyPI file hash, because pip-compile in the Linux container drops the macOS-only `appnope` the notebook kernel needs and hash mode then refuses the lock on macOS.
- Move CI's inline check of the generated MWAA Serverless workflow into `airflow/serverless/validate_generated_workflow.py`, which the workflow tests also run locally: the file must match the DAG's current definition and hold no account ID, ARN or task revision. The inline copy had drifted from the DAG without any local check failing.
- Deployment fixes from the Oct 6 2026 first deployment. The deploy user's Glue template allows tagging the Glue job; the EC2 template allows reading security group rules. `run_fhir_setup.sh` reads the seed bundle prefix from the setup task definition, because the targeted foundation apply does not record that output. The simulator's blood-pressure readings are exported from the current Synthea cohort; the quickstart says to export them before pushing images.
- Adopt Conventional Docs for authored project Markdown after complete document and workflow review. Correct metadata, American Psychological Association (APA) Title Case headings, contents, terminology, procedure anatomy, source provenance and recorded verification boundaries; preserve historical evidence and the separate README structure.
- Correct selected-environment loading, model-command configuration, per-vital ordering, blood-pressure freshness and teardown guidance.
- Select each patient's less frequent tagged simulator scenario for runs planned to cover the full 30-minute window. Ties and short runs use a seed or random choice; startup tags do not replace analytical window, class and leakage checks.
- Ignore isolated load-test events in the live dashboard. Close ordinary subscribers for a consistent measurement baseline because their shared WebSocket connections still receive events.
- Preserve the first load-runner failure when cleanup also fails, bound WebSocket shutdown and report sanitized failure categories, accepted writes and missing observations.
- Keep end-to-end reports local and ignored rather than committing them.

### Fixed

- The ingestion workflow's webhook check accepts the Lambda's own 401 refusal (`Invalid webhook secret`) as reachable: every webhook route needs the shared secret, which the workflow does not hold, so the check failed on every run. A 200 `healthy` still passes; any other answer fails.
- `e2e.aws_ingestion` reads each task's status from its last try; task instance IDs end in the try number, so an earlier failed try hid the final result.
- The Grafana panel checks query a fixed range and the Capacity census is compared with the warehouse over the same hours.
- Deployment policies: invoke `GET /patients/*/early-warning`, manage the Grafana ECR repository and read partitions in the ML Glue database. The policy renderer fills `FEATURE_WINDOW_TABLE_NAME`.
- The FHIR setup task runs with 0.5 vCPU and 4 GiB: the reference extract reads every Synthea bundle, about 2 GiB at peak for the 100-patient output.
- Teardown storage cleanup previews and empties the Grafana ECR repository with the other four; it was left out.
- MyPy skips the ignored `artifacts/` folder, where replay captures keep their own `record_frames.py`.
- `tools.install_tools` rebuilds a tool environment whose Python was removed, as by a Homebrew upgrade, instead of crashing while checking its version.
- The planted precursor no longer turns waveform dropouts into valid readings. Drifting an SpO2 of 0 or a respiratory rate below 4 used to clamp it to the lowest valid value (SpO2 50, respiratory rate 4), so 537 readings that the processor would have rejected appeared only in deterioration encounters, a marker of the label. Dropouts now stay as they are and are rejected. The recalibration chose the same scales: `planted-signal-v2` is unchanged; the calibration seed's model AUC is 0.802 (was 0.798) and NEWS2 0.691 (was 0.705). The new warehouse NEWS2 cross-check exposed it.
- Remove scenario tags an updated batch encounter no longer carries; HAPI keeps a resource's existing tags on update, so an encounter whose scenario changed held both tags.
- Read the BIDMC SpO2 channel when a record's header puts format fields before the signal name (bidmc19n); records past 10 were never fetched before the 100-patient cohort.
- Handle the GitHub OpenID Connect (OIDC) provider and deployment-role outputs when a refresh-only plan sees no application-stage resources. Remove the unused Fast Healthcare Interoperability Resources (FHIR) seed-prefix outputs; the setup runner reads the task definition.
- Allow the realtime processor to publish metrics to the `HealthcareRealtime/LoadTest` namespace; load-test metrics were denied. Allow the deploy user's EC2 template to disassociate Elastic IP addresses, so the destroy no longer stops on the NAT address.
- Wait for HAPI FHIR to pass its health check before the setup task loads the cohort, instead of failing on HTTP 502 from a new target.
- Record load-test WebSocket subscriptions that close before the run ends, with their close codes, so missing deliveries show their cause.
- Verify processor write health and actual write denial before replay submission. Remove the run's temporary Deny policy and verify processor writes during cleanup, then remove only owned terminal messages after a bounded quiet interval. The original deployed replay and load failures still require fresh live verification.

### Added

- Add three Grafana dashboards, Pipeline Operations, Quality and Safety and Capacity, written once in `deploy/grafana/dashboards/` and rendered for a warehouse by `scripts/grafana/render_dashboards.py`, which rejects Postgres-only SQL so the same source can serve Athena. The local stack renders and provisions them on start. The dbt model `fact_unit_hourly_census` (cohort reference models) gives the census, admissions, discharges and admission NEWS2 of each unit and hour, with a Soda contract and an `add_hours` macro. `e2e.local_grafana` runs every panel query through Grafana's API and compares the census panel with the warehouse; `e2e.local_warehouse` checks the census against a count from the raw admissions.
- Add `notebooks/model_comparison.ipynb` and `python -m e2e.analysis`, which checks the frozen analysis plan's SHA-256 before reading data and then executes the notebook headless for the study and the null-control arm, keeping each executed notebook and `results.json` under `artifacts/e2e/analysis/`. `jobs/analysis/run.py` runs every pre-specified analysis and applies the plan's decision rules. The study's supplemental oxygen and new confusion occur only in deteriorating encounters and separate the labels, so H1's joint test is a GEE score test and the naive and GEE minute models use the five continuous vitals; both are recorded deviations from the plan, the second made after study results were seen. The AUC code and the run's completeness check reject missing scores, after a diverged GEE fit had produced a meaningless AUC.
- Add the `jobs/analysis/` library for the simulation study's pre-specified analysis. `roc` computes the AUC, DeLong's test for two correlated ROC curves and percentile intervals from a bootstrap that resamples whole split groups. `data` loads each arm's analysis set from the local warehouse (encounters with a complete NEWS2, their minute rows with 5-minute measures carried forward, the moderator groups) and refuses a plan whose SHA-256 differs from the frozen one. `models` holds the grouped folds, the naive logistic, GEE logistic and gradient-boosted models scored out of fold and the GEE tests of the vital signal and of moderation, clustered by split group with the bias-reduced covariance.
- Add the dbt models `fact_encounter_news2` (NEWS2 at the end of each encounter's feature window from the last value of each parameter, missing when a parameter is) and `fact_encounter_trend_features` (each vital's least-squares slope over the feature-window minute means). `e2e.local_warehouse` checks both against an independent Python computation from the batch records.
- A synthetic attending roster and an attending provider on every simulated admission. `scripts/nppes/provider_roster.py` builds `dbt/seeds/provider_history.csv` from `config/provider_roster.json`: 24 Washington physicians in eight NUCC specialties with production-format NPIs, realistic names and type 2 history. A one-time NPPES NPI Registry check replaced 6 NPIs and 16 names that matched real clinicians and keeps counts only. The simulator and the batch record the attending by NPI, chosen by unit and admission date and independent of the scenario. `fact_admissions` carries the attending provider version and specialty. `dim_encounter` uses the attending instead of the round-robin placeholder. The Glue table, Soda contract and local warehouse check follow.
- Run the cohort reference models on AWS. The daily workflow's new `extract_cohort_reference` task runs the FHIR setup task's `reference` command, which writes demographics, payer history, facilities, admissions and waveform split groups as JSON lines to `reference/cohort/` in the data bucket; Glue tables read them and dbt builds the reference models with `cohort_reference_enabled`. `run_fhir_setup.sh reference` runs it by hand. The setup task may write only that prefix and read the resource map; MWAA may start the setup task and pass only its roles. Add Soda contracts for the five reference models and a `parse_timestamp` macro for Athena.
- Add `python -m jobs.calibration.calibrate`, which calibrates the planted signal on a separate seed without writing to HAPI: a logistic regression on `vital-features-v3` reaches an AUC of 0.802 and NEWS2 0.691, with the null control at 0.501 and 0.480. It also checks that the planted age 65+ heart-rate effect (RQ3) is detectable: its 95% CI lay below 0 on 10 of 10 extra seeds. `config/planted_signal.json` is now `planted-signal-v2`. Add `services/news2.py`, NEWS2 scoring from one observation set. `e2e.local_warehouse` checks that the calibration features equal the warehouse's.
- Add the planted signal of the simulation study (`config/planted_signal.json`, `planted-signal-v1`): a seeded early-warning trend in the feature window of 75% of deterioration encounters, with half the heart-rate drift for patients aged 65 and over, plus a null control that plants nothing. The batch now gives each patient six encounters, three per scenario, from 1 June 2026 so every stay is finished; it writes `planted_truth.json` and generates the null control with `--signal null_control` into its own folder and HAPI encounters. The live simulator plants the same precursor (`SIMULATOR_PLANTED_SIGNAL`). Each run starts at its own seeded point of the patient's waveform record with a seeded offset per vital, so a patient's runs never copy each other. The loader records each patient's birth date for the age group. `e2e.local_cohort` checks the truth file and the visible trend. `LOCAL_WAREHOUSE_SIGNAL=null_control` loads the null control into its own `raw_null_control` and `analytics_null_control` schemas.
- Add three bedside measures BIDMC lacks to every 5-minute observation set: body temperature (LOINC `8310-5`), inhaled oxygen concentration (`3150-0`) and consciousness as ACVPU (`67775-7` with its AVPU answers plus `LA6560-2` for confused, stored as an ordinal 0 to 4). They flow through the catalog, the webhook (event schema `1.2`, with coded answers), the processor, the latest-vitals table, the API, the dashboard's focused review, Glue, Great Expectations, Soda and dbt (feature schema `vital-features-v3`). Each patient's temperature baseline is seeded near 36.8 degrees Celsius, because Synthea records temperature only at illness visits. The label definition is unchanged.
- Add the local warehouse. `python -m jobs.local_warehouse.load` loads the batch into the local Postgres `raw` schema in the Glue job's row format; `python -m jobs.cohort_reference.extract` adds Synthea demographics, payer history, facilities and the batch admissions; `python -m jobs.local_warehouse.dbt` runs the dbt models there through dbt-postgres 1.11.0. A regenerated batch replaces its earlier values, also when a reading keeps its observation ID and receive time. Cross-adapter macros keep the Athena SQL unchanged. With `cohort_reference_enabled`, dbt builds `dim_patient_version` (payer SCD2 with demographics), `dim_facility`, `dim_unit` (facility and unit with a care level from the `hospital_units` seed), `fact_admissions` and `fact_encounter_minute_features`. `ml_training_dataset` then splits by waveform split group. `python -m e2e.local_warehouse` checks it end to end. SQLFluff lints both sides of the switch. See Local Stack.
- Each simulator and batch encounter is now a simulated admission: a Synthea facility, a unit, an admitting diagnosis and a 24 to 144 hour stay, seeded by the run. Only inpatient-grade disorders from the simulator's admitting list qualify; a patient with none gets a common medical admission marked `simulator_fallback`. The loader stores each patient's facilities and disorders in the resource map. Batch encounters are completed stays with status `finished` and are updated by identifier. The second encounter starts 14 days after the first.
- Add `COHORT_SIZE` (10 by default, as on AWS; up to 100 for local development) for the loader, the resource-map check and the simulator. Synthea now generates 100 adult patients, aged 18 to 90 (`AGE_RANGE`), with seed `4817263` instead of 12345; The AWS cohort is their first 10. The simulator's blood-pressure file covers all 100. Patients 54 to 100 reuse BIDMC waveform records 1 to 47 from their midpoint, with a seeded per-vital offset and noise so their feature-window vitals differ from the first use.
- Add `python -m jobs.batch_vitals.generate`: two 30-minute encounters per patient, one per scenario, created in HAPI FHIR and written as NDJSON in the stream processor's event format, with a manifest. Records the processor would reject are counted, not written; reruns reuse the encounters and write identical files. `split_groups.json` maps each patient to its waveform record for a record-grouped model split. `python -m e2e.local_cohort` checks the 100-patient cohort and batch end to end.
- Add a local Docker stack (`deploy/local/compose.yaml`) with Postgres 16.15, HAPI FHIR v8.10.0-3 and Grafana 13.2.3 on localhost-only ports. HAPI assigns UUID patient IDs; Grafana reads the warehouse through a read-only role. `scripts/local/local_stack.sh` generates local passwords once and starts, stops or resets the stack; `python -m e2e.local_stack` checks it end to end. See Local Stack.
- Add prose, metadata and pinned Markdown syntax hooks, their continuous integration (CI) setup and real-hook regression samples. The locked installation and 91-case real-hook verification passed at `034488c`; the adoption review also checks the ignored private guide explicitly. Permit only `details` and `summary` for collapsed historical context while retaining the other Hypertext Markup Language (HTML) syntax guard.
- Block commits that leave references to removed functions, classes, config keys, Terraform declarations, dbt models, Airflow task IDs or dependencies, in each commit and over each pushed range in CI. Report unused code (vulture), unused or undeclared dependencies (deptry), unreferenced files and unread `.env.example` entries in warn mode.
- Add dbt-project-evaluator 1.4.0, locked with dbt_utils 1.4.1 and disabled unless a run opts in. Add an Airflow DagBag test for import errors, unused task IDs and unwired tasks.
- Install every pipeline stage from a hash-pinned lock compiled from its `.in` source: the development environment, the Airflow package, the dbt, Soda and simulator images and the Glue job. The Glue job now pins `s3fs`, which had no version. `tools/compile_requirements.py` recompiles the locks in Linux containers and a `requirement-locks` hook keeps each lock in step with its source.
